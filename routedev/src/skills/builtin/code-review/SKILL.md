# Skill: code-review

> **目标**：对代码变更做结构化审查，按严重级别输出可执行建议
>
> **触发词**：代码审查、review、审查、检查代码、找 bug

## 审查流程（强制）

1. **收集改动**：优先用 `git diff` 获取改动；无 git 时按文件路径读
2. **影响分析**：对每个高风险改动点，调用 callers/impact 找调用方
3. **只深读风险相关实现**：避免漫无目的扫全文件
4. **按严重级别输出**：正确性 > 安全 > 回归 > 风格

## 严重级别定义

| 级别 | 含义 | 示例 |
|------|------|------|
| P0 正确性 | 逻辑错误、崩溃、数据丢失 | 空指针、死锁、写入失败 |
| P1 安全 | 权限绕过、注入、信息泄漏 | SSRF、XSS、敏感日志 |
| P2 回归 | 破坏现有功能的改动 | 接口签名变更、行为变更 |
| P3 风格 | 可读性、命名、结构 | 命名不一致、缺少注释 |

## 输出格式

每条发现一行：
```
[级别] 文件:行号 — 问题描述 → 建议修复
```

## 禁止

- 跳过影响分析直接评论风格
- 重写整段代码（仅指出问题，让作者决定）
- 在未读源码的情况下猜测实现
