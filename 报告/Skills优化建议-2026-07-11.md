## 1) systematic-debugging/SKILL.md 关键替换

把“验证/构建”相关硬编码从 Gradle 改为：

```markdown
## 验证命令（按项目选择，不要写死）

| 项目类型 | 优先命令 |
|----------|----------|
| RouteDev / pnpm TS | `pnpm typecheck`、相关 `pnpm test -- <path>` |
| Node 通用 | 项目 README 中的 test/build |
| 其他 | 用户指定或 package.json/scripts |

没有新鲜命令输出，不准宣称已修复。
```

并在 Phase 1 增加：

```markdown
- [ ] 区分：代码逻辑 / 装配未接线 / 配置门控 / 环境问题
```

反模式追加：

```markdown
- 把“默认关闭配置”当成 bug
- 把“动态 import 可选模块”当成缺失
- 修症状不修装配/接线
```

---

## 2) verification-before-completion/SKILL.md 关键替换

删除/弱化 `rtk err gradlew build` 硬门槛，改为：

```markdown
## 命令选择

优先顺序：
1. 用户指定命令
2. 项目 README / package.json scripts
3. 通用回退：

| 生态 | 示例 |
|------|------|
| RouteDev | `pnpm typecheck`、`pnpm test`、`pnpm build` |
| pnpm/npm 通用 | `pnpm test` / `npm test` |
| 无测试 | 手工复现步骤并记录结果 |
```

对照表追加：

```markdown
| 瘦身完成 | 门禁脚本/清单指标 | 只删了文档描述 |
```

## 3) writing-plans/SKILL.md 关键替换

```markdown
**计划保存位置（按仓库实际选择）：**
1. 用户指定路径
2. 项目已有 `蓝图与Phase/` 或 `docs/plans/`
```


```markdown

```
