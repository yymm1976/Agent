### 阶段 3：权限体系接线（TD-04 ~ TD-09）

**目标**：修复 PermissionEngine 接线断裂，建立完整的权限校验链路

#### TD-04：PermissionEngine 接入 onActing

**现状**：
- `PermissionEngine` 在 `app-init.ts` 创建并配置，但 `check()` 零调用点
- `loop.ts` 的 `onActing` 中间件仅跑 `QualitySignalMiddleware` + `PolicyEngine`
- 沙箱级（read-only/workspace-write）、默认 deny 规则、审批级旋钮**静默失效**
- 设置页 UI 声称"已接线"但实际未生效

**修复方案**：

1. **创建 PermissionMiddleware**（`src/agent/middleware/permission-middleware.ts`，新建）：
   ```typescript
   export class PermissionMiddleware implements Middleware {
     constructor(private permissionEngine: PermissionEngine) {}
     
     async onActing(ctx: MiddlewareContext): Promise<void> {
       const { toolName, args } = ctx;
       const decision = await this.permissionEngine.check(toolName, args, ctx.mode);
       
       if (decision === 'deny') {
         ctx.metadata.permissionDenied = true;
         ctx.metadata.permissionReason = 'PermissionEngine denied';
       } else if (decision === 'confirm') {
         ctx.metadata.requiresConfirmation = true;
       }
     }
   }
   ```

2. **注册中间件**（`app-init.ts` 或拆分后的 `app-init-agent.ts`）
3. **loop.ts onActing 增强**：检查 `ctx.metadata.permissionDenied`
4. **补集成测试**：`tests/agent/permission-middleware.test.ts`
5. **UI 文案更新**

**验收**：PermissionEngine.check 有调用点、sandbox 生效、deny 规则生效、集成测试通过

#### TD-05：静默 catch 治理

**现状**：
- 全项目 50+ 处空 `catch {}` 块
- 上一轮已修复 5 处（filesystem-discovery/project-memory/memory-store）
- 剩余 45+ 处分布在：trace-collector(8)、experiment-manager(7)、branch-persistence(3)、checkpoint-manager(3)、ccr-cache(3)、profiles/manager(2)、plugins/registry(2) 等

**修复方案**：

1. **按风险分级处理**：
   - **P0 高风险路径**（数据丢失/不可恢复）：branch-persistence(3)、checkpoint-manager(3) → `logger.error`
   - **P1 中风险路径**（可观测性/实验数据）：trace-collector(8)、experiment-manager(7) → `logger.warn`
   - **P2 低风险路径**（缓存/降级）：ccr-cache(3)、profiles/manager(2)、plugins/registry(2) → `logger.debug`
   - **其余散布**：逐文件 grep `catch {` 或 `catch (e) {` 后跟空语句体

2. **统一日志格式**：
   ```typescript
   } catch (e) {
     logger.warn(`[模块名] 操作失败: ${e instanceof Error ? e.message : String(e)}`);
   }
   ```

3. **批量验证**：运行全量测试确认日志添加不影响行为

**验收**：
- `grep -r "catch {" src/` 结果为 0（所有 catch 块都有日志）
- 全量测试通过
- tsc 零错误
