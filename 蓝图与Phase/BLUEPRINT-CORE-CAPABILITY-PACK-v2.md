# RouteDev 整改蓝图：核心 + 外置包

> **日期：** 2026-07-11（v2 修订：四层架构 + 冷处理策略）  
> **状态：** 执行中  
> **路线：** 核心最小化 + 外置包冷处理 + 按需加载  
> **目标版本区间：** v4.6.0 → v4.8.0  
> **原则：** 先分层、再冷处理、后按需启用；不删可用模块，只退默认路径

---

## 1. 产品定位（冻结）

**一句话：** 面向个人开发者和小团队的低成本、可靠、可控的桌面编程 Agent。

**核心承诺：**

1. **省钱**：默认走便宜模型；费用与 token 可见、可设上限  
2. **好用**：单 Agent 主路径能稳定完成读码、改码、跑测、回滚  
3. **可控**：用户明确知道 Agent 会做什么；权限固定清晰，不暗中升级  
4. **可扩展**：高级能力通过外置包按需启用，不污染默认路径

**明确不做（当前版本默认路径）：**

- 默认开启多 Agent 编排  
- 默认全自动多步自治  
- 动态渐进式信任  
- 隐式经验水平推断  
- 为 5% 场景付出 100% 默认维护成本

## 2. 四层架构

```text
┌──────────────────────────────────────────────────┐
│ Core（默认开启，必须可测、可维护）                  │
│ 路由/Token、单 Agent Loop、核心工具 ≤10、          │
│ 固定权限、Checkpoint、项目规则、基础记忆            │
├──────────────────────────────────────────────────┤
│ Extended Pack（中等偏下，默认关，保留接口并维护）   │
│ Multi-Agent 协作、Goal 高级编排、对抗审查           │
├──────────────────────────────────────────────────┤
│ Standard Pack（外置包，默认关，冷处理，不扩建）     │
│ 浏览器/Web、代码地图、Trace/Scorecard、导入生态     │
├──────────────────────────────────────────────────┤
│ Freeze（冻结，停止接线，不承诺）                    │
│ 渐进信任动态升级、隐式经验适配、高级图算法          │
└──────────────────────────────────────────────────┘
```

### 层级定义

| 层 | 默认状态 | 维护策略 | 用户可见 | 删除门槛 |
|----|----------|----------|----------|----------|
| **Core** | on | 主动强化、必须有测试 | 主界面 | 不可删 |
| **Extended Pack** | off | 中等偏下优先级维护、修 bug、不扩新功能 | 设置页"高级"区 | 60 天零启用 |
| **Standard Pack** | off | 冷处理：修崩溃级 bug、不扩功能 | 设置页"扩展"区 | 90 天零启用 |
| **Freeze** | off | 停止一切接线 | 不出现 | 与下一个清理窗口一起删 |

### 2.1 Core（加强）

| 能力 | 原因 | 成功指标 |
|------|------|----------|
| 手动选模型 + 2–3 级成本路由 | 省钱差异化 | 单任务均费用可测且下降 |
| Token/预算追踪与可见性 | 用户信任 | 设置页与对话页均可见 |
| ReAct 单 Agent 主循环 | 主路径 | 对话场景闭环通过 |
| 核心工具 ≤ 10 | 降低误选与 token | 默认注册数 ≤ 10 |
| 固定权限（allow/confirm/deny） | 安全可控 | 无动态信任升级 |
| Checkpoint / diff / 回滚 | 改坏可恢复 | 回滚成功率可测 |
| 项目规则 / 上下文压缩 | 长期可用 | 规则加载与压缩稳定 |
| MCP + Skill 按需扩展 | 扩展面正确 | 默认不注入全部定义 |

### 2.2 Extended Pack（中等偏下，保留接口并维护）

用户明确需要时可启用，有一定社区需求但非默认必需。

| 包名 | 当前模块 | 启用方式 | 维护级别 |
|------|----------|----------|----------|
| `pack.goal-advanced` | goal-runner 高级编排、GoalVerifier 迭代 | `/goal` 自动按需 | 修 bug + 保 sequential；不加新编排模式 |
| `pack.multi-agent` | multi/orchestrator + blackboard + worker | 设置开关 + spawn_agent 注册 | 修 bug；不加新 Agent Profile |
| `pack.adversarial-review` | cross-model-reviewer + adversarial 逻辑 | 设置开关 + /review 命令 | 修 bug；不加新审查维度 |

**Extended Pack 规则：**
- 默认 off，用户手动启用
- 接口保留完整，不破坏类型契约
- 修崩溃和数据安全问题，不加新功能
- 启用时有设置说明和成本提示

### 2.3 Standard Pack（外置包，冷处理）

几乎用不到或仅在特定场景有价值。保留代码、保留接入接口，但不投入维护。

| 包名 | 当前模块 | 启用方式 | 冷处理策略 |
|------|----------|----------|------------|
| `pack.browser-web` | browser / web_search / web_fetch | 设置开关 | 不新增爬取能力 |
| `pack.code-map` | code-map / code_graph_query | 项目首次启用时索引 | 不加新语言 |
| `pack.harness` | trace-replayer / scorecard | `/replay` `/scorecard` | 不加新评分维度 |
| `pack.import-ecosystem` | cite / import / macros | 设置页导入区 | 不加新导入源 |
| `pack.compose` | compose-pipeline / work-modes.compose | Skill 或模板 | 不加新模板类型 |

**Standard Pack 规则：**
- 默认 off，冷处理
- 仅修崩溃级 bug
- 不投入新功能开发
- 接口保留但允许内部重构简化

### 2.4 Freeze（冻结）

价值未证明或已被更好的方案替代。停止一切接线与扩张。

| 模块 | 冻结原因 | 处理方式 |
|------|----------|----------|
| Progressive Trust 动态升级 | 安全框架反对动态提权 | 停止接线；保留类型定义 |
| Implicit Feedback / Experience Adaptation | 无社区需求 | 停止接线；保留类型定义 |
| KnowledgeGraph 高级算法（PageRank/社区检测） | tree-sitter+SQLite 已够用 | 默认关；保留存储接口 |
| /goal 并行调度与冲突检测 | sequential 已够；并行无真实使用 | 冻结代码路径 |
| Compose 自动选择 | 应由用户显式触发 | 移除自动路由 |

## 4. 判定标准

### 进 Core 的条件（三条全满足）

1. 服务 Core 场景（改码/省钱/回滚/可控）  
2. 有入口 + 生产调用 + 测试  
3. 默认成本可接受（不显著增加 token/启动时间）

### 进 Extended Pack 的条件

- 有明确用户场景但非高频  
- 有社区需求信号（社区讨论、竞品保留）  
- 保留后维护成本可控（不牵动 Core）

### 进 Standard Pack（冷处理）的条件

- 几乎用不到但有接入接口  
- 删不如留（删除需要改接口/测试/文档的成本高于保留）  
- 不投入新功能

### 进 Freeze 的条件

- 价值未证明  
- 有更好替代方案  
- 继续接线会污染默认路径

## 7. 执行纪律

1. **先量后砍**：无调用日志不删生产模块  
2. **冷处理优先于删除**：几乎用不到的模块进 Standard Pack，不删代码  
3. **Core 变更必须有测试**  
4. **Extended Pack 修 bug 不扩功能**  
5. **Freeze 模块停止一切接线**  
6. **每 Phase 更新**：`TECH_DEBT_TRACKER.md`、`CODEMAP.md`、审查提示词已知清单  
7. **禁止**以"看起来高级"为理由把 Freeze 拉回默认路径
